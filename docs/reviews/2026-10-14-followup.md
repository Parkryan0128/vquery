# Follow-up review — 2026-10-14

This pass reviewed ownership, execution, workload generation, CLI behavior, benchmark persistence, and the Python runner against the supported contracts. It also replaced the long planning-style README with an implementation guide and moved detailed measurement rules to `docs/benchmarking.md`.

## Fixed issues

1. **Owning-table copy assignment split the memory owner from its buffers.** Default member assignment changed `Tables::budget` or `HashTable::budget_`, while vector copy assignment retained the old allocator. The reproduced tests showed allocations still charged to the destination's previous budget. Copy assignment now constructs a complete copy before moving it into the destination. Tests check both layouts, later hash growth, independent data, release accounting, and rollback after a partial copy allocation fails.
2. **A second output error could suppress failure metadata.** After a raw write failed, `fclose` could fail again and skip the metadata update in the same try block. A real file-size-limit test reproduced this after successful samples had already been written. Close and metadata update now have separate failure handling; the original error is preserved and the metadata records completed samples plus failure when it can still be written.
3. **Benchmark help could report success after stdout failed.** The benchmark help path now flushes and checks the stream, as the query CLI already did. A child process with a zero file-size limit verifies the nonzero exit and structured error.
4. **Summary validation accepted incomplete controls and invalid row counts.** It now requires all three single-thread engine controls, checks selected/joined/result counts against query semantics and validation, and rejects tracked memory above the configured limit. Tests cover missing/parallel-only controls, impossible counts, and complete valid records for every query. The existing 27-run exploratory dataset remains readable.
5. **The CLI integration test assumed GoogleTest's default download location.** Coverage configuration with an external FetchContent source exposed the assumption. CMake now supplies the actual dependency source path to the test.

## Test and code changes

- Added 16 GoogleTests and expanded the Python suites from 14 to 25 named tests. The result is 40 CTest entries containing 63 named tests, with parameter/failure sweeps inside them.
- Added generated skew/join-boundary checks, an actual concurrent budget contention test, failure sweeps through parallel merge/result allocation, result lifetime checks, and subrange/reopen tests after partial initialization.
- Extracted calibration into a small function so threshold, rounding, even-median, overflow, and rejection behavior can be checked without relying on wall-clock speed. An executable test still exercises actual warmup/calibration and persisted output.
- Added text/JSON agreement, CLI numeric/rate boundaries, output-path escaping, checksum tuple errors, initial budget failure, and late file-write failure checks.
- Split summary sample/manifest validation into named functions, removed compound Python statements, formatted the scripts consistently, made the file owner noncopyable, and enabled warnings on both executable entry points.
- Removed obsolete milestone instructions, repeated checklists, and portfolio pitch text from README. The source map, ownership rules, supported scope, build commands, and remaining performance work are retained.
