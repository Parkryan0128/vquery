# Code review — 2026-10-14

Scope: all engine, allocator/storage/hash, CLI, benchmark orchestration, record-validation, build-preset, and test code. Changes are committed directly to main under the repository workflow.

## Findings and fixes

| Finding | Trigger and effect | Resolution / regression evidence |
| --- | --- | --- |
| Buffered output errors were missed | A small CLI result stayed buffered; a failed final write could still exit zero. Reproduced with a zero file-size limit. | Explicitly flush result/help output before checking the stream; integration tests require `output_failed`. |
| Hash insertion could retain an invalid reference | Passing an existing aggregate value to `insert_unique` at the growth boundary retained a reference into the old allocation. | Copy the value before rehashing; test an aliased insertion across the 0.7 load boundary. |
| Public pipeline boundaries were inconsistent | Row scans accepted invalid ranges; a zero-size direct batch scan could fail to advance; missing join inputs could construct an invalid plan. | Validate ranges, table shape/query, join/filter inputs, and batch sizes before consuming data. |
| Cancellation could be delayed by empty batches | Filter/Join could loop internally over rejected or unmatched batches without returning to the worker's cancellation check. | Propagate the shared token into batch sources and check at physical-batch boundaries. Deterministic tests cancel during an all-rejected stream and between scan batches. |
| Stale CMake options could contaminate publication runs | Reconfiguring an existing Release directory did not clear `VQUERY_SANITIZER` or restore `VQUERY_BUILD_TESTS`. An empty CTest run could appear successful. | Presets explicitly reset these options; no-test runs fail; the runner and summary inspect build/protocol metadata. Integration tests reconfigure a deliberately contaminated cache. |
| Single-engine manifests could validate only themselves | A row-only manifest supplied its own result as the timing expectation without any cross-engine comparison. | Always add all three single-thread controls; record and verify cross-engine agreement. Test an actual row-only manifest. |
| Malformed records could abort every summary | Valid JSON such as `null` or an array reached dictionary operations, raising uncaught exceptions. Weak typing also admitted inconsistent artifacts. | Share strict decoding/configuration validation; reject duplicate keys, non-finite numbers, invalid types, malformed manifests, and inconsistent publication metadata. Bad runs are excluded while valid neighbors remain usable. |

## Validation

- Debug and Release CTest suites include independent references over 100 seeds, worker failure/cleanup, and the new regressions.
- The Python integrations exercise executable output failures, cache reset, an empty CTest directory, row-only validation, and the full 15-configuration smoke workflow.
- The stricter reader was checked against all 27 previously generated exploratory core runs; all remain readable.
- Clang-Tidy 22 scanned all nine production translation units with Clang static-analyzer, bugprone, and performance checks. No Clang static-analyzer finding was reported. The allocator deliberately copies its shared budget during move to keep moved-from vector allocators usable; that diagnostic does not justify changing ownership semantics.
- Linux CI runs Clang/GCC Debug/Release, ASan/UBSan, and TSan; macOS CI runs Debug. The workflow result for the commit is the authoritative cross-platform check.

These checks cover the supported in-memory workload and its artifacts. They do not establish a performance improvement or complete the pending Linux profiling study.
